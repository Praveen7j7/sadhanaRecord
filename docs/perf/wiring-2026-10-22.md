harmless.

- `auth.lookup` from `screens/SignUp.svelte:44` sends any token left in localStorage (the sign-up screen is only
  reachable signed-out, so usually empty, but a stale token is sent — exactly what `lib/api.js:5-8` says must not
  happen on a public route).
- `push.register` (`lib/push.js:63`, the "with nobody" registration) and `push.unsubscribe` (`lib/push.js:93`)
  send the token too. The server ignores it (`api.js:259` skips `sessionCtx` for PUBLIC), so this is a disclosure,
  not a failure.

**Devotee code landing in a `staff-` chunk — one real case.** `lib/staff.js` (week arithmetic, `closesSpec`,
`mondayIST`) is imported by `devotee/Group.svelte`, `ui/WeekPicker.svelte` and 7 staff files. Rolldown names its
shared chunk after the module, `staff`, so the plain rule `assets/[name]-[hash].js` (`vite.config.js:138`) emits
`assets/staff-Ebyr6bqJ.js` — indistinguishable from the staff-only prefix. Consequences, verified in `dist`:
`Group-BvFKu9fM.js` and `WeekPicker-gY5-RKla.js` both `import … from "./staff-Ebyr6bqJ.js"`; `sw.js` precache has
`Group-*` and `WeekPicker-*` but **not** `staff-Ebyr6bqJ.js` (globIgnore `assets/staff-*.{js,css}`, `vite.config.js:15`),
and the runtime rule caches it CacheFirst as staff code (`:104`). A group leader opening **My group** always needs
the network on first open and gets "Could not load this screen" offline (`App.svelte:133`). Fix: rename
`lib/staff.js` (e.g. `weekmath.js`) or make the staff prefix something a module name cannot collide with.

- Duplicate patterns: none. Alias: `/learn` ≡ `/hearing` (`routes.js:51,53`), no nav item, no comment.

- Signed-out list duplicated: `routes.js:34 PUBLIC_PATHS` (used only by tests) vs `App.svelte:22 PUBLIC`.

**Service-worker precache (`dist/sw.js`, 123 entries):**

  by `ui/ExportSheet.svelte:18-19`, which is in `STAFF_UI` (`vite.config.js:19`). Rolldown splits the two deps as
